## 三、明确的新需求/变更（有结论）

### 3.1 平台定位收窄为内部采购管理（L50–88、L366–415）

- 正规公开招标走交易公司，不在本平台；平台只做承接项目的工程后续采购 + 办公普通采购。
- 审批、合同、签约全部留在 OA，平台内不做。
- 平台内仅保留两个审批：① 采购代理（中介）上传内容须经采购部门审核后才能发布；② 经办部门填写的采购公告须经采购部门审核后才能发布。**（已被五.5 第 5 条作废：最终口径为仅保留立项审核）**

### 3.2 供应商体系（L105–362）

- 极简注册：只填企业名称、信用代码、联系人电话、登录密码；采购部门后台对照 OA 已审批清单批复即成为供应商，不重复录入细节，不同步 OA 业绩等敏感数据（L169–180）。
- 双登录：首选短信验证码，其次账号密码；因部分供应商只有座机，手机号不强制。短信复用公司现有应急管理系统的短信平台接口，不新增费用（L194–235）。
- 三分类互斥规则：劳务、材料、其他三类；劳务与材料互斥（只能选其一），但两者都可兼做「其他」（其他类公开、不入库，如咨询、技术服务）（L263–316）。
- 年度剔除用「是否有效」标志而非删除：Excel 导出清单 → 标记剔除 → 重新导入实现批量失效；保留历史记录，失效后不能参与新采购但历史可见（L317–362）。

### 3.3 敏感字眼清洗（L526–553）

因审计会按「招标/公开」字眼套严格标准，内部实际是采购，文字上回避「公开招标」类表述。与仓库 2026-07-26 术语清洗口径一致，本会议再次确认。

### 3.4 数据分析（L554–700、L1193–1316）

- 材料名称与计量单位分离存储、展示时合并，否则吨/千克混排无法比价（L560–600）。
- 新增统计维度：① 可选时间范围内单个供应商参与采购次数（柱状图按月）；② 单项物资采购单价走势；③ 下浮率对比表（限价 vs 单价 vs 总价），明确「不用图，有对比表就行」（L1288–1295）。
- 全部支持 Excel 导出，供领导查看和审计自查筛选；同物异名的模糊归并由人工在导出后处理（L1193–1256）。
- AI 报价异常分析扩展：现有 vs 均价保留，新增 vs 限价对比，上下浮动双向预警（过低要怀疑质量）（L1299–1316）。

### 3.5 三价体系与成交价调整（L701–1006）

- 预算价（限价）、报价、成交价三价并存；正常 80% 以上报价 = 成交价（L893–897）。
- 成交价调整功能（新功能，demo 未覆盖）：分标段统一价场景下需调整成交价；默认不调整则成交价 = 报价；调整时支持对清单批量改价；多标段统一价只改一次、五个供应商默认同价成交（L988–1005）。

### 3.6 清单与标段（L1007–1168、L1976–2144）

- 清单 Excel 导入为发布侧主路径：几百项清单不可能逐项填。
- 「导什么认什么」：系统不建物资库、不设物料编号、不做物资校验（L1067–1134）。
- 投标方必须按发布的清单模板填写，上传时系统校验项次缺失/不符并提示「第几项不存在」（L1135–1168）。
- 「采购包」改为「标段」模型：基本信息处加「是否设置标段/标段数」字段；时间等共性内容作表头统一填一次；每标段只有内容、金额（预算价）、清单三项差异；每标段单独导入一份 Excel 清单（L1976–2144）。

### 3.7 发布流程（L1523–1560、L1827–1955）

- 删除「采购需求库」环节：需求部门立项在 OA 完成，平台直接发布需求；发布向导中需求步骤与供应商要求合并。
- 分步向导改为整页一次填完，且整个发布内容需可打印（陈部长要打印留底）（L1853–1862、L1947–1955）。
- 评审/开标地点给默认选项 + 手动填写（L1863–1876）。

### 3.8 阳光平台分工（L1551–1555、L1590–1604）

本平台发布后，阳光平台只发结果；中选通知书仅达到一定金额才出，普通采购只出结果公告。

### 3.9 开标评标（L1428–1530、L2512–2524）

- 内部评标从简：不要求同室/摄像头/临时账号；评标同事用各自固定账号登录，在待办中看文件、录意见、打分即可（类 OA）。
- 开标设时间段 + 提醒（L1491–1499）。
- 唱标功能先按标准保留，不删（L1428–1445）。
- 评标组成 5 人：财务管理部 1 + 财务部 1 + 经办部门 1 + 专家 2（L2512–2524）。

### 3.10 角色与权限（L2420–2596）

- 删除/搁置监督员角色：目前无监督员，制度暂不改，该角色先不做，可由管理员兼。
- 管理员分两层：流程管理员（采购负责人审核）与系统管理员（配置/手册）分开。
- 采购单位内部权限分级：财务/经办部门账号只能查看，采购部账号可发布、对比，按账号定制。

### 3.11 标书与投标文件（L2160–2210、L2359–2364、L2597–2878）

- 标书按模板自动生成：发布端填完信息即自动生成标书；不同采购方式（直接采购/比选等）模板不同；陈部长会后提供公告模板、标书模板、评标表（L2325–2347）。
- 投标文件在线填报 + 自动生成 PDF，取代上传 PDF 查重：不做查重，改为系统提供模板在线填写、自动生成 PDF（公司名称等自动带入），下载打印盖章即可；承诺书自动生成。
- 供应商人员/证件库：供应商各自维护本公司信息、人员、证件（身份证、从业资格证等），一次录入、投标时勾选复用；证件有效期校验，过期不可选；业绩不入库（文件大、无固定模板）；资格审查表格式待与陈部长单聊。

### 3.12 费用与收款（L3003–3339）

- 报名费不收；不做微信支付二维码（手续费 + 资金安全审核更严，L3225–3312）。
- 改为收款管理闭环：中标公告写明收款账号 → 中标方公对公/个人转账 → 系统入口上传回单凭证 + 填关键信息 → 财务核实确认 → 出具中选通知书（L3248–3281）。
- 专家费由招标代理线下发放，不进系统（L3319–3324）。
- 需求说明书中费用部分先预留，未定是否招标代理前不开发支付（L3186–3214）。

### 3.13 招标代理（L3361–3380）

固定合作一家、签 3 年，不建代理库抽取。

### 3.14 协作与验收机制（L2898–2976）

- 需求说明书/合同/验收口径按本次讨论调整；立项流程还在走、需求书未封版，开发方按今天结论改需求书，保证验收匹配（L2944–2965）。
- 以后每次会议做纪要/签到留痕；开发方按操作步骤截图做用户手册发群。
- 对接顺序：发布前 → 开标 → 结果三步走，最后做数据分析。

2. 零星采购/直接采购是否上平台（L1605–1655）：四种采购方式中前两种是否纳入、金额门槛设多少（举例 5 万），未最终定。
3. 是否启用招标代理及金额门槛（L3114–3160、L3337–3351）：400 万以上疑似集中走代理，但还没定，由蓝总决定；代理未定则代理费/中标服务费收不收也无结论。
4. 费用收取主体与路径（L3100–3186）：若走代理，费用由成交单位付给代理；平台只可能收进公司账户，无法代转，待代理决策后定。
5. 专家库（L1386–1407）：内部由采购方指定人员（给名单勾选）；代理场景下专家怎么抽还没跟代理落实。
6. 唱标是否保留（L1428–1445）：先按标准做，待招标代理方提需求再裁剪。
7. 项目列表导出筛选条件（L1793–1812）：要加筛选条件（金额大于 X 等），具体条件清单到时候再列。

## 五、设计思想（介绍方讲解意图）

- 「参照规范、内部从简」总原则（L477–553）：框架向外部招投标平台规范靠拢（投标团队熟悉行业规范），但内部使用不必那么严格；目标是提高效率、实用为主，不做高大上的（L2977–2985），对外显得规范即可。
- 清单是数据分析的源头（L1368–1375）：只有把采购清单结构化录入而非富文本粘贴（L2013–2024 明确批评采购包用富文本「后面没法做数据分析」），后续比价、下浮率分析才成立。这是采购包改标段 + Excel 清单的核心动机。
- 避免双系统维护（L1096–1134）：不建物资库/物料编号，名称、计量单位按业主口径多变，维护两套数据成本高；同名异物统计拆开的风险由导出后人工处理兜底。
- 演示驱动、逐环节对接的开发节奏（L416–476、L1877–1928）：陈部长无法一次性给出全部字段口径，约定开发方做到哪一步就以 Word 文档（流程 + 页面元素）发给他逐项确认，再约现场投屏会逐项过；先按规范改版，再按他的口径逐项调整（L1337–1345）。
- 系统内嵌规则代替人工监督（L2443–2451）：「系统很大一个功能就是把规则嵌进去把关」。
- 评审放权给专家、系统不深管标段归属（L831–870）：标段归属由专家确定后公布，系统只记录。
- 未来扩展预留（L2993–3001）：好用的话二级单位/同级单位可能并入，届时加登录端口，先做好自己用。

## 五.5、会后补充口径（2026-07-27 口头补充，优先级高于会议讨论稿）

以下为会后补充的简化总原则，按「新口径优先」规则，与会议讨论内容冲突时以本节为准：

1. **尽量简化字段和流程**：太多字段太麻烦，没必要，怎么简单怎么来。
2. **能自动生成的就不要人填写**；**能上传文件的就不要手动填写**。
3. **创建项目五步改成一个页面**：原分步向导废弃，创建项目整页一次完成（与 3.7 发布流程「整页一次填完」口径一致并进一步明确到创建项目环节）。
4. **采购不需要外部关联**：直接在创建项目页面创建需求，不关联外部系统/外部需求来源。
5. **审核点收敛**：整个平台只有一个审核点——创建项目（立项）后审核，其他环节都不需要审核（2026-07-27 口头确认：「两个」为口误，实际只有立项审核）。会议 3.1 的「代理内容审核 + 公告发布审核」两个审批口径**作废**。
6. **字段取舍思想**：保留最小必要字段，可以缺了补，但不要多了删。
